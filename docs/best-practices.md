# Best practices

A checklist for production. Each item links to the details.

## Setup

- [ ] **Create sources and registries once, at module scope**, or with `useMemo`. A new source means an empty cache. A new registry re-validates every block.
- [ ] **Keep fallbacks and `onIssue` stable** (module constants or `useCallback`).
- [ ] **Put one `CmsProvider` near the root** of the tree that shows content. Several `CmsPage`s can share it.
- [ ] **Server code imports `@contentcore/core`; client code imports `@contentcore/react`.** Required in Next.js App Router ([details](embedding.md#nextjs-app-router)).

## Content

- [ ] **Block ids are stable and unique**, generated by the CMS rather than derived from position ([content model](content-model.md#rules-for-stable-content)).
- [ ] **Never rename a registry key** without an alias or a migration.
- [ ] **Schema changes are backwards-compatible.** New fields are optional or have defaults, and breaking changes ship with a migration.
- [ ] **Embedded sections live under a reserved prefix** (`/sections/…`) and stay out of routing and sitemaps.
- [ ] **Rich text uses the `html` block's node tree**, not HTML strings. Import legacy HTML once with `htmlToNodes`.

## Performance

- [ ] **Prefetch on intent:** `usePrefetch()` on link hover and focus.
- [ ] **Prime client caches with server-loaded pages** (`source.prime(page)`), so the first client navigation is instant.
- [ ] **Serve ETags** from your content API. Revalidation becomes a `304`, with no download or parsing.
- [ ] **Send CDN headers:** `s-maxage` + `stale-while-revalidate`.
- [ ] **Keep pages reasonably sized.** Rendering 1,000 blocks takes about 2.3 ms server-side; split long pages with sections or pagination.
- [ ] **Prefer sync schemas.** They render on the first pass, including on the server.

## Reliability

- [ ] **Leave the cache on** (the default). Set `staleIfError` to how long stale content is acceptable during an outage.
- [ ] **Ship a static snapshot** as the last source in a `createFallbackSource(…, { onError: "next" })` chain for critical pages.
- [ ] **Wire `onIssue` and `onRevalidateError`** to your error tracker and metrics.
- [ ] **Give every region sensible fallbacks.** Full pages show a not-found or error UI with retry; embedded sections render nothing.
- [ ] **Use short timeouts at the edge** (`timeoutMs: 3000`, `retry: { retries: 1 }`).

## Security

- [ ] **Capabilities are UI hints only.** Every write endpoint checks permissions on the server.
- [ ] **Cache per-user content per user.** Draft, preview and personalised content use a per-request source or `cache: false`, never a shared module-level cache ([details](sources-and-caching.md#per-user-content-read-this)).
- [ ] **Keep CMS tokens on the server.** Browser sources call your own API, and secrets come from the environment (`${CONTENT_API_TOKEN}`), never the bundle.
- [ ] **Opt in to `script`, `iframe`, `embed` and the like only for content you trust**, and prefer a dedicated block (for example a `video` block with a schema-validated provider and id) to allowing raw iframes.
- [ ] **Escape page JSON embedded in HTML** for hydration (replace `<` with `<`; see `examples/node-server`). Escape values placed in `<title>` and `<meta>`.
- [ ] **Add a Content Security Policy.** The `html` block never needs `unsafe-inline` scripts.

## Operations

- [ ] **Invalidate on publish:**
  - Server frameworks: a publish webhook calls `revalidatePath` (Next.js) or `source.invalidate(slug)`.
  - Browsers: refresh within `ttl`, or on demand.
- [ ] **Version the content model**, and keep the migrations for as long as old documents exist.
- [ ] **Run your app's tests against both static fixtures and the API source.** They share one contract, so the same assertions apply.
